## 1. 노트 쓰기

**내 폴더에 `<장번호>.md` 파일을 만들면 끝입니다.**

```bash
# 성수가 1장을 끝냈다면
mkdir -p content/istio-in-action/성수
vi content/istio-in-action/성수/1.md
```

내용을 쓰고 push합니다.

```bash
git add . && git commit -m "docs: 성수 1장 노트" && git push
```

몇 분 뒤 배포가 끝나면 이렇게 됩니다.

- 1장 동그라미에 **체크가 들어옵니다**
- 그 동그라미를 누르면 **내 글이 열립니다**
- 지난번보다 진도가 늘었으면 **축하 애니메이션**이 뜹니다

<img src="docs/screenshots/progress.png" width="280" alt="진도 화면 — 체크된 챕터와 오늘의 퀘스트" />

**체크박스는 따로 없습니다.** 파일이 있으면 그 장을 끝낸 것으로 봅니다.

### 쓸 수 있는 것

평소 쓰던 마크다운 그대로입니다.

````markdown
## 핵심 개념

- **서비스 메시**: 네트워킹 관심사를 인프라로 옮긴다
  - 사이드카 프록시가 트래픽을 가로챈다

> 클라우드에서는 인프라가 일시적이라는 가정으로 앱을 만든다

| 패턴          | 하는 일                           |
| ------------- | --------------------------------- |
| 서킷 브레이커 | 오동작하는 서비스에 부하를 끊는다 |

```bash
istioctl install --set profile=demo -y
```

[Istio 공식 문서](https://istio.io)
````

이렇게 나옵니다.

<img src="docs/screenshots/note.png" width="280" alt="노트 화면" />

### 알아두면 편한 것

- **포맷 검사를 받지 않습니다.** 들여쓰기나 줄바꿈을 편한 대로 쓰세요.
- `<script>` 같은 걸 넣어도 화면에 나오기 전에 걸러집니다.
- 노트를 안 써도 진도 화면은 멀쩡히 돌아갑니다.

## 2. 이미지 넣기

**1단계.** 이미지 파일을 여기에 넣습니다.

```
public/images/notes/istio-in-action/1-1.png
```

이름은 `<장번호>-<순번>.png`로 지어주세요. 나중에 찾기 쉽습니다.

**2단계.** 글에서는 `images/`부터 시작하는 경로를 씁니다.

```markdown
![서비스 메시 개념도](images/notes/istio-in-action/1-1.png)
```

> ⚠️ `public/`은 빼고 씁니다. `public/images/...`가 아니라 `images/...`입니다.

크기는 안 적어도 됩니다. 알아서 넣어줘서 이미지가 늦게 떠도 글이 밀리지 않습니다.

## 3. 목차 고치기

`content/istio-in-action/chapters.md` 하나만 고칩니다. **사람별로 복사하지 마세요.**

```markdown
# Istio in Action 학습 진도

## 1장. 서비스 메시 소개

- [ ] 1.1 더 빨리 가려 할 때 마주치는 어려움
- [ ] 1.2 애플리케이션 라이브러리로 해결하기
```

- `## `로 시작 → **챕터** (진도 화면의 동그라미 하나)
- `- [ ] `로 시작 → **절**

**`[ ]`와 `[x]`는 손대지 마세요.** 완료 여부는 노트 파일이 있는지로 정해집니다.

## 4. 일정 바꾸기

`content/istio-in-action/schedule.md`의 표를 고치면 "오늘의 퀘스트"가 바뀝니다.

```markdown
| 기간                    | 챕터 | 소주제                   |
| ----------------------- | ---- | ------------------------ |
| 2026-07-13 ~ 2026-07-19 | 1, 2 | 서비스 메시와 Istio 시작 |
| 2026-07-20 ~ 2026-07-26 | 3, 4 | 데이터 플레인            |
```

| 항목 | 이렇게 쓰세요        | 예시                        |
| ---- | -------------------- | --------------------------- |
| 날짜 | `YYYY-MM-DD`         | `2026-07-13`                |
| 챕터 | 쉼표로 **하나 이상** | `7` · `1, 2` · `1, 2, 3, 4` |
| 기간 | 서로 **겹치지 않게** | 앞 주가 끝난 다음 날부터    |

> ⚠️ 형식이 틀리면 **에러 화면이 뜹니다.**
> 그 줄만 조용히 넘어가면 한 주가 통째로 사라지는데 아무도 모르기 때문입니다.
> 에러가 뜨면 어느 줄이 문제인지 화면에 나옵니다.

## 5. 나만 다른 일정 쓰기

진도가 남들과 다를 때 씁니다. **내 폴더에 `schedule.md`를 만들면 그게 우선합니다.**

```
content/istio-in-action/
├── schedule.md        ← 기본 (내 파일이 없으면 이걸 따름)
└── 채영/
    └── schedule.md    ← 채영만 이걸 따름
```

이번 주에 1~4장을 몰아서 따라잡고 싶다면:

```markdown
| 기간                    | 챕터       | 소주제            |
| ----------------------- | ---------- | ----------------- |
| 2026-08-05 ~ 2026-08-11 | 1, 2, 3, 4 | 처음부터 따라잡기 |
| 2026-08-12 ~ 2026-08-18 | 5, 6       | 트래픽 제어       |
```

반대로 한 주에 한 장만 나가고 싶으면 `| 2026-08-05 ~ 2026-08-11 | 7 | 관찰 가능성 |`처럼 씁니다.

형식은 [4번](#4-일정-바꾸기)과 같습니다. 파일을 안 만들면 기본 일정을 따르니 굳이 만들 필요 없습니다.

## 6. 사람 추가하기

**1단계.** `content/istio-in-action/members.json`에 추가합니다. 적은 순서가 화면 순서입니다.

```json
[
  { "name": "성수", "avatar": "avatars/성수.webp" },
  { "name": "채영", "avatar": "avatars/채영.webp" }
]
```

**2단계.** `public/avatars/<이름>.webp`에 사진을 넣습니다. 카드 폭을 꽉 채우니 **1000px 16:9**로 준비하세요.

```bash
# PNG를 받았다면 — 화질은 그대로, 용량은 1/4
cwebp -q 82 채영.png -o public/avatars/채영.webp
```

노트 폴더는 안 만들어도 됩니다. 첫 노트를 쓸 때 만들면 됩니다.

## 자주 막히는 것

**Q. push했는데 화면이 그대로예요**
배포에 1~2분 걸립니다. [Actions 탭](https://github.com/dev-study-club/istio-in-action/actions)에서 초록 체크가 떴는지 보세요.

**Q. 이미지가 깨져요**
경로에 `public/`이 들어갔는지 보세요. `images/notes/...`로 시작해야 합니다.

**Q. 에러 화면이 떠요**
`schedule.md`나 `chapters.md` 형식이 틀린 경우가 대부분입니다. 화면에 어느 줄이 문제인지 나옵니다.

**Q. 내 장이 진도 화면에 안 보여요**
`schedule.md`의 어느 주차에도 그 챕터 번호가 없으면 안 나옵니다. 일정에 넣어주세요.
